## Fedora support
- `pkg_install` in `tools/common.sh`: install hints per distribution (apt names mapped to dnf:
  xvfb → xorg-x11-server-Xvfb, x11-utils → xdpyinfo, x11-xserver-utils → xrandr, xauth →
  xorg-x11-xauth, pipewire-bin → pipewire-utils, dmsetup → device-mapper, linux-modules-extra →
  kernel-modules-extra, v4l2loopback-dkms → akmod-v4l2loopback (RPM Fusion), ffmpeg →
  ffmpeg-free). Used by check.sh, start.sh, build-stick.sh; `docs/setup.md` lists both.
- **x11vnc 0.9.17 refuses to run in a Wayland session**, even for an Xvfb display ("Wayland
  sessions are as of now only supported via -rawfb ... Exiting."); with `-quiet` the log stayed
  empty and krdc said the server doesn't exist. `start.sh` runs it as
  `env -u WAYLAND_DISPLAY XDG_SESSION_TYPE=x11 x11vnc` (`X11VNC` array, same pid as before) and
  warns when an x11vnc quits right away (`check_vnc`).
- **pw-play of PipeWire 1.6 reads stdin as a sound file** (libsndfile: "Format not recognised",
  the audio pipeline restarted every 2 s). `play_stereo` passes `--raw` when `pw-play --help`
  knows it (older PipeWire has no such option and plays raw anyway).
- Ctrl+C in the terminal also killed Xvfb (same process group), so Chromium and QtCar lost their
  screen before the teardown stopped them: segfaults at every stop (CenterDisplayDe in
  libQtCore, chromium, chromium-fullscreen). Xvfb now runs under `setsid`. After that QtCar
  stops cleanly; the three S Chromium services still print "Segmentation fault" at stop, without
  an X error (their own SIGTERM handling?), and `logsummary` reports them as problems: open.
- SELinux (enforcing) didn't get in the way of the chroot in these runs.
- A camera set to `/dev/video10` gave "Not a video capture device": that's a v4l2loopback device
  of the user's (scrcpy, phone camera), it only has a picture while scrcpy feeds it. Not a bug.

## Test runs (VNC, both firmwares)
- Model 3 2019.20.4.2 (`--vehicle --audio --gps`): 9 services, no restarts, no segfaults, audio ok.
  `model-s` is at least as good as `main` for the Model 3.
- Model S 2026.8.3 (`--config tesla-s.conf --vehicle --audio --gps`): 19 services, center
  display + cluster. One QtCar restart on the first start (changed VAPI_* DVs, expected). In 3 min
  15 248 ERROR lines, almost all the panel loop without escalator: `could not open gpio
  BMP-LCD-PWR-EN /sys/class/gpio/gpio467/value` (5846 + 2924 "Can't access"), `CenterDisplay
  escalator read-dpcd failed` (4384), `DriverDisplay escalator read-dpcd failed` (546),
  `Escalator failed to read-dpcd` (275), `could not access escalator drm-status-detect` (137).
  Also `Invalid method name _data_get_value_request_` (115) and
  `/run/chromium/policies/chromium-app` (34).
