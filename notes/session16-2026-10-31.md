# Session 16 (2026-10-31): a cellular modem as the car's LTE

Branch `cellular-modem`. The question: can a cellular modem work on the Model 3 or S, and which
modems. Everything below was tested in the sandbox only; no real modem yet.

## The car's own stack (why it isn't used)
- Both firmwares: oFono 1.17 (`/usr/sbin/ofonod`) with Tesla's `tesla` plugin (S/X also `iris`;
  `modem-type` reads `/var/lib/ofono/modem`). Modems: Telit LE940B6 ("titan"; NA/RW/CN firmware
  in `/deploy/telit`), on the S/X also Quectel AG525R-GL ("iris", `etc/ofono/iris.conf`).
- The modem sits on its own board on the car's Ethernet: AT commands over TCP
  `192.168.90.60:50950` (`etc/ofono/tesla.conf`, `modem-command`), data on VLAN 20 (`eth0.2`,
  192.168.20.2, gateway .1, MTU 1430, `etc/sv/ofono/run`), power through GPIOs or the gateway
  (`modem-power`, `gpio -e LTE-MDM-STATUS`).
- ofonod has the stock udevng plugins (huawei, zte, sierra, quectel, ublox, he910, mbm, ...)
  but no QMI/MBIM drivers and no `telit.c`; QtCarConnMan only reads the modem `/tesla` with
  `org.ofono.Tesla.Diagnostics`. A USB modem through the car's oFono would at best be an old
  AT/PPP stick, and probably invisible to the UI.
- Not done (option 2 of the discussion): emulate the Telit endpoint (AT server on
  192.168.90.60:50950 backed by a real modem, a 192.168.20.1 gateway on eth0.2, GPIO stubs), so
  the car's ofonod + QtCarConnMan run unchanged. Network changes: laptop/stick only.

## What the status bar reads (sandbox experiments)
Values set one at a time (Model 3: HTTP :4220; S: D-Bus DataSetValueRequest to DvServer and
CenterDisplay via `podman exec`), status bar cropped after each step:
- `LINK_linkState`: `cellular` -> cell icon; `Wifi`/`wifi` -> Wi-Fi icon.
- `CONN_cellConnected`: false/invalid -> the cell icon crossed out ("no service").
- `CONN_cellSystemMode` -> the label (NetworkStatusBarItem::getCellNetworkLabel: uppercased,
  startsWith 2G/4G/GSM/LTE/EDGE; anything else "3G"; China cars 4G for LTE). No 5G label.
  `CONN_cellNetwork` doesn't change it; on the S it is an enum (libQtCarGUI `CellNetworkNameMap`:
  0 Unknown 1 GPRS 2 EDGE 3 UMTS 4 HSDPA 5 HSUPA 6 HSPA 7 LTE 8 GSM 9 CDMA 10 WCDMA 11 LTE5GCN
  12 5GNSA 13 5GSA 14 NGRAN 15 SNA).
- `CONN_cellSignalBars` 0-5: 0 and 1 just the dot, 2 one bar ... 5 all four.
- Same on both firmwares.
- Internet: Model 3 `OPTION_dataPlan` is `Full`, `GUI_canUseInternet` stays true on cellular.
  S: `None` -> cellular makes `GUI_canUseInternet` false; `OPTION_dataPlan=Full` (string over
  D-Bus) makes it true. QtCar persists it in QtCarSettings.db (QVariant int, 1 = Full); the
  sandbox's DB was reset to 0 afterwards (`podman unshare sqlite3`, the directory is a subuid's).

## Implementation
- `tools/host-connectivity.py --cellular`: each cycle `ip -j route get 1.1.1.1`; if that
  interface is a ModemManager modem's (net ports, connected bearers' interfaces), publish the
  cellular values (mmcli JSON: access technologies, signal quality, operator); else withdraw them
  (and the S's previous data plan) and present the host as Wi-Fi as before. `--cellular-only`:
  nothing when not on the modem (Model 3, `--wifi`). `--http URL`: Model 3's QtCar HTTP values.
- `./tesla`: `CELLULAR=0|1|auto` (`--cellular`), auto = ModemManager has a modem; `check` lists
  the modems. The stick: `CELLULAR=auto`, modemmanager + qmi/mbim proxies + ppp + usb-modeswitch +
  mobile-broadband-provider-info (names checked on packages.debian.org), and a read-only
  NetworkManager profile `cellular` (gsm.auto-config) in /usr/lib/NetworkManager/system-connections.
- End to end in the sandbox with a fake `mmcli`/`ip` (and on the S a fake `chroot` forwarding to
  `podman exec`): Model 3 LTE 4 bars / 3G 1 bar / LTE full / Ethernet -> crossed out; S LTE ->
  Wi-Fi again. The S run lags one cycle there because each value is a `podman exec`.

## Sandbox fix
`sandbox.sh` failed with "exec /host/lib64/ld-linux-x86-64.so.2: Permission denied" (SELinux
enforcing on Fedora 44: container_t may not execute the host's loader/gdb). It now runs podman
with `--security-opt label=disable`.
