## Charging (ChargeModelSX in tesla-can.py)
Probe (scratchpad probe.py, as session 14's: set one signal through the running tesla-can.py,
compare ~1750 data values from qtcar-vehicle :4030; names from libQtCarVAPI strings):
- `BMS_packCurrent`/`BMS_packVoltage` -> `VAPI_batteryCurrent`/`Voltage`; QtCarVehicle averages
  them into `VAPI_chargeAveragePower`.
- `CHG_lineCurrent`, `CHG_inputVoltage`, `CHG_inputPowerUI` -> `VAPI_chargerCurrent`, `Voltage`,
  `Power`; `CHG_pilotCurrent` -> `VAPI_chgPilotCurrent`/`maxPilotCurrent`;
  `BMS_chgLineCurrentAvail` -> `VAPI_maxLineCurrent` (the UI's current range);
  `BMS_chgTimeToFull` (h) -> `VAPI_chargeTimeToFull`; `BMS_fastChargerPresent` -> fast charger.
- The UI sends `MCU_requestLineChargeCurrent` and `MCU_requestChargeEnable` (MCU_request 0x69),
  `MCU_chargeTerminationPct` (MCU_bodyControl 0x7; 4.8 until the limit was ever set, 81 at 80 %).
- The center display's Charging tab (2026 S) has only the limit, the current and Stop/Start; the
  session figures are on the cluster (`ClusterChargeInfoPanel`): time remaining, energy added
  (QtCar's own, from the energies), kW, and mi/hr = `GUI_chargeAveragePower` x 1000 /
  `VAPI_ratedWattHourPerMile` (ChargingUtils::currentChargeRateMilePerHour, UIFramework).
  QtCar's ChargingManager copies `VAPI_chargeAveragePower` into `GUI_chargeAveragePower`
  (averageChargePowerChanged), but here it never got a change of it: the rate stayed 0. Set over
  D-Bus (CenterDisplay DataSetValueRequest) the cluster showed 25 mi/hr at once. So
  host-connectivity.py got `--copy SRC=DEST` (reads QtCarVehicle's value over HTTP every 15 s,
  sets it in QtCar), and start.sh passes `--copy VAPI_chargeAveragePower=GUI_chargeAveragePower`
  with --vehicle.
- ChargeModelSX: while CHARGING the line current is the UI's request up to the station's pilot
  (panel "Station", default 32 A at 240 V), the battery (`X_batteryLevel`) fills with 92 % of
  the power into 81 kWh, the time to full follows, at the limit COMPLETE (currents 0). Stop/Start
  switches CHARGING/STOPPED (`charge-stopped` preset).

## MAME keys (scroll wheels)
`STW_status` (0x17, ETH): `STW_leftButtons`/`rightButtons` bit 0 bottom, 1 middle, 2 top ->
`STW_leftBottom`/`Middle`/`Top`; `STW_leftWheel`/`rightWheel` ticks (255 = -1) ->
`STW_leftScroll`. The same `STW_*` values the Model 3's arcade uses. `STW_ACTN_RQ`'s
`StW_Sw*_Psd` drive nothing. The panel's Arcade tab (Model 3 names `VCLEFT_swc*`) maps to them
through `VIRTUAL_SX` (bit mask kept per side); for the S the tab shows only the scroll wheels.

## USB music
QtCar's MediaV2::USBAccess (in QtCar, not the media server) lists `StorageUtils::usbMediaFolder()`
and adds entries starting with `<folder>/usb-`; it rescans when `GUI_usbMediaMounted` changes
(mounterd sets it; through com.tesla.DvServer, not CenterDisplay). gdb in the sandbox (sandbox.sh
-x, a tbreak after the call, QString dumped as x/48xh): usbMediaFolder() = `/mnt/media` on the S,
whatever `[usb] media_path` says. start.sh/sandbox.sh mount the folder at /mnt/media/usb-music
for the S. Then: fs hash, indexer (2 files), USB in the media source list (the source waits for
the audio system: needs `--audio`), tags shown, the media server plays (`Playing, NoError`).
The media server's session bus and gvfs jobs aren't needed.
